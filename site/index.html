Method

  • Application under test: 2AM Notes Pro (React + Vite), Semester II content, with its real Google Apps Script backend code run locally so latency can be controlled exactly.
  • Scenario (identical in every suite): open the Subjects page; the app requests the library (listLibrary); the check is that the “Java Programming” card is visible.
  • Latency: 0, 500, 1000, 1500, 2000 ms added on the server to the listLibrary response — the same for both frameworks.
  • Strategies: Selenium implicit wait (5 s), Selenium explicit wait (WebDriverWait 10 s), Cypress fixed wait (cy.wait(1000)), Cypress network wait (cy.intercept + cy.wait('@listLibrary')).
  • Check rule: “strict” — after its wait, each strategy makes one immediate check (the Selenium explicit wait's wait is the check). “retry” — the Cypress suites again with Cypress's default 4 s assertion retry, as Cypress tests are usually written.
  • Runs: 10 per configuration and latency, each a full page load in a visible Chrome window; time measured inside the test from navigation to the check.

Limitations

  • 10 repetitions per configuration (time-constrained), on one Windows machine — treat small differences with care.
  • Latency is added server-side to one request, not with real network shaping.
  • Visible (headed) browsers add rendering time equally to both frameworks.
